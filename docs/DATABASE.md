# PostgreSQL и граница экономики

Prisma 7 и adapter-pg используют PostgreSQL. Все модели имеют @@schema("arcade"). Runtime adapter явно задаёт arcade; Prisma config принудительно задаёт schema=arcade, включая журнал миграций. Тест проверяет, что прикладные таблицы и _prisma_migrations находятся только в arcade.

| Модели | Назначение |
| --- | --- |
| Player | Проверенный профиль и настройки |
| AuthSession, AuthChallenge | Хеши сессий, сроки/отзыв, одноразовые challenges |
| RoomSnapshot, RoomMember | Настройки, состояние, приглашение, состав и presence |
| MatchSnapshot, MatchAction | Checkpoint, версия, журнал, статус |
| MatchParticipant, PlayerStatistic | История результата, статистика, рейтинг |
| RecoveryEvent | Возврат, переподписка, передача хоста, архивация |
| RequestReceipt | Идемпотентность комнат |
| EconomyOperation | Резерв для будущей интеграции, сейчас не используется |

Discord ID — строка. Dev/test допускает dev: идентификаторы; production-вход их не создаёт. Токены сессий/приглашений не сохраняются открытым текстом. Checkpoint содержит приватное состояние и не выдаётся через API.

## Миграции

- 202611090001_arcade_platform создаёт новую схему и модели.
- 202611090002_active_membership добавляет частичный уникальный индекс активного membership с ограничением ожидания блокировки.

В первой миграции неполные имена таблиц: выполнять её нужно **через Prisma с данным prisma.config.ts**, задающим search_path arcade. Не исполняйте SQL вручную с search_path public. Второй индекс явно квалифицирован arcade.

~~~powershell
pnpm db:local
# В другом терминале:
pnpm db:migrate:local
pnpm db:migrate:test
~~~

Эти команды используют только созданные проектом loopback-базы arcade_dev и arcade_test. migrate deploy применяет только новые миграции. Нет reset, db push, drop или удаления данных.

Для новой отдельно согласованной Arcade-БД: проверьте URL/роль, создайте backup, передайте ARCADE_DATABASE_URL через secrets, затем:

~~~powershell
pnpm --filter @rize/database exec prisma migrate status
pnpm --filter @rize/database exec prisma migrate deploy
~~~

Это инструкция, не автоматический deployment hook. Здесь миграции применены только локально. Runtime-роль должна иметь права только на arcade; отдельной роли миграций нужны DDL-права. Предпочтителен отдельный PostgreSQL service/database.

## Сохранность

Комнаты и memberships архивируются, история не удаляется. Результат и статистика фиксируются одной транзакцией; retries не начисляют повторно. Прерванные из-за суточного отсутствия матчи сохраняются без выигрыша/проигрыша. Восстановление проверено настоящим рестартом backend.

Автоматическое удаление архивов/auth receipts не реализовано. Перед долгой эксплуатацией определите retention и backup policy. UI показывает последние 50 завершённых матчей и первые 50 игроков рейтинга.

## Экономика бота

База бота не подключалась и не исследовалась. Python-код, баланс и таблицы экономики не изменялись. EconomyPort — контракт будущей интеграции без новой валюты и реальных начислений.

Нужно отдельно согласовать API/роль, источник баланса, награды, идемпотентность и транзакции. Локальный журнал не гарантирует однократное внешнее начисление. Production-подключение к базе бота и её миграции требуют отдельного разрешения.
