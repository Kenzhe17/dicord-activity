## Согласованность

Клиент отправляет намерение, requestId и expectedVersion. Actor извлекается из серверной сессии. PostgreSQL — источник истины для сессий, комнат и матчей. RoomDirectory и MatchRuntime восстанавливаются из БД на время операции.

Изменения выполняются транзакционно под общим PostgreSQL advisory lock. Snapshot, action log, результат и статистика фиксируются атомарно; уникальные индексы дополнительно защищают retries и единственное активное membership игрока. Публикация клиентам выполняется после commit.

Общий lock ограничивает пропускную способность. Read-проекции не удерживают lock; следующий снимок устраняет временное отставание отображения. Большая нагрузка и много реплик не испытаны. Перед масштабированием нужны блокировки по агрегатам, оптимизация checkpoints и транспорт публикаций.

## Комнаты и восстановление

Приватные комнаты исключены из поиска. Для первого входа требуется отдельный случайный invite token; в БД — SHA-256 и срок 24 часа. Хост может перевыпустить его, отозвав прежний. Просмотр, подписка и матч проверяют membership.

Повторный join безопасен. Готовность проверяет версию; create/ready/start используют durable receipts. Выход передаёт хоста следующему участнику; пустая/закрытая комната архивируется без удаления истории. Во время матча выход из состава запрещён, но можно отключиться и вернуться.

Socket.IO хранит в памяти только соединения/подписки. Клиент повторяет subscribe после reconnect. Сервер читает БД, обновляет presence каждые 15 секунд и проверяет изменения подписанных комнат раз в секунду. Views отправляются персонально каждому сокету. Нет heartbeat 45 секунд — offline; после двух минут отсутствия хост ожидающего лобби передаётся активному участнику.

Очистка каждые 30 циклов архивирует ожидающие комнаты без активности 30 минут. Активная партия сохраняется минимум 24 часа отсутствия всех участников, затем получает interrupted без результата/рейтинга. Checkpoint и recovery events сохраняются. Bootstrap восстанавливает сессию, комнату, матч и настройки.

## Игровой контракт

GameModule<State, Action, Settings, View> задаёт metadata, stateVersion, Zod-схемы, начальное состояние, валидацию/применение действий, getPlayerView, результат, serialize/restore. Время и seed приходят с сервера; движок не выполняет I/O.

Registry различает planned определения и исполняемые модули. Запуск проверяет количество игроков, готовность и настройки. Дурак запускается в подкидном/переводном режиме на 2–6 игроков. Монополия — классика/быстрая/командная 2×2 на 2–6 игроков (команды — ровно 4); состояние, кубики и колоды детерминированы seed'ом checkpoint, скрытая колода клиенту не отдаётся (только счётчики). Мафия — 6–12 игроков, роли, ночные действия, голосование и встроенные чаты; правила в games/mafia/RULES.md. Sandbox подключается только по флагу вне production.

Envelope: protocol, roomId, matchId, requestId, expectedVersion, action. Runtime проверяет membership, идентификаторы, версию и легальность. Идентичный requestId возвращает актуальное view; другое содержимое отклоняется. Restore воспроизводит журнал и сравнивает snapshot. Checkpoint, чужие скрытые поля и полный журнал клиенту не выдаются.

Лимит журнала — 100000 действий. Сейчас replay выполняется при чтении/действии: для длинных игр нужна оптимизация. Результат и статистика записываются один раз. По решению пользователя новые матчи сохраняют статистику и исходы без изменения rating. ratingDelta=0; существующие рейтинги не пересчитываются.

Для новой игры создайте workspace, реализуйте модуль и тесты, зарегистрируйте его в apps/server/src/games.ts и подключите игровой UI. Правила Дурака утверждены в games/durak/RULES.md; правила UNO/Мафии ещё не реализованы.

## Авторизация и приватность

SDK ready → одноразовый challenge → authorize(code, identify) → серверный обмен → /users/@me → persistent session → SDK authenticate и сравнение ID. Activity context/participants служат интерфейсу, не доказывают identity или membership.

Discord access token используется только для SDK authenticate. API использует отдельный случайный bearer: в БД SHA-256, срок 24 часа и отзыв; в браузере sessionStorage вкладки, не URL. Logout отзывает сессию и отключает сокеты. Повторный SDK-вход обновляет профиль и отзывает переданный прежний токен.

Strict Zod, Origin allowlist, HTTP/socket rate limits, payload limits, no-store и CSP защищают транспорт. Production запрещает mock и sandbox. История доступна владельцу, рейтинг содержит публичный профиль и статистику. Автоматические тесты не заменяют внешний аудит безопасности.

## Таймеры Дурака

GameModule получил необязательные getSystemAction/applySystemAction и getRoomCapacity. Sandbox и прежние checkpoints остаются совместимыми. Таймерные действия записываются в тот же checkpoint/log с system=true и серверным actor. HTTP/Socket.IO не позволяют отправить системный ход от клиента.

Poller проверяет активные матчи каждую секунду. Под PostgreSQL advisory lock повторно восстанавливает версию, выбирает максимум одно системное действие и атомарно сохраняет его вместе с результатом. Человеческое действие перед обработкой проверяет актуальный таймер; expired version возвращает конфликт/ошибку и свежий view.

Ошибка checkpoint/часов одного матча изолируется: остальные таймеры и рассылка состояний продолжаются. В журнал попадают только matchId и имя класса ошибки, без приватного состояния и сообщения драйвера. Повреждённые checkpoints автоматически не переписываются; оператору нужно расследовать зарегистрированную ошибку.

Срок каждого решения — 30 секунд. Timeout делает разрешённую авто-атаку, взятие или пас. При отсутствии heartbeat всех участников время приостанавливается; при возвращении сохраняется остаток. Рестарт backend записывает recover и даёт неприостановленному матчу минимум 30 секунд, без каскада ходов за downtime. Для обнаружения переподписок действует стартовый grace 30 секунд. При N репликах каждый новый процесс может один раз продлить срок: начальное deployment по-прежнему рассчитано на одну реплику.

Личные действия/подсветка вычисляются на сервере. Клиент импортирует только типы игрового пакета и не получает seed/колоду/чужие руки. SVG-карты написаны специально для проекта. Готовность после конфликта версии повторяется один раз с актуальным состоянием и новым requestId.

HTTP rate limit для подтверждённых сессий считается по player ID, чтобы общий NAT/Discord proxy не объединял всех участников. Непроверенные токены и auth endpoints используют IP bucket; смена поддельного bearer не обходит ограничение. Лимитер локален процессу: для большого multi-node deployment потребуется общий store.

## Переподключение и штатная остановка

При остановке Fastify сервер вызывает `io.close()`: закрывается транспорт, и Socket.IO Manager клиента автоматически подключается снова. `disconnectSockets(true)` здесь запрещён: он отправляет namespace DISCONNECT и отключает автоматический reconnect клиента. Явный `socket.disconnect(true)` остаётся для отзыва доступа и logout.

На каждом `connect` клиент заново подписывается на текущую комнату с проверенным session token. Статус «Подключено» означает подтверждённую подписку и, если в комнате есть матч, получение его персонального view. Пока выполняется обмен, отображается «Синхронизация…». Старые acknowledgment callbacks отделены номером поколения соединения; при cleanup удаляются обработчики и таймеры. Безопасно повторяется только запрос подписки, игровые действия автоматически не отправляются заново.

Диагностика `[arcade:realtime]` содержит только событие, разрешённую причину отключения, признак automatic и номер попытки. Сервер логирует фиксированные realtime-события, число соединений/наличие матча и разрешённую причину. Токены, заголовки, ID игроков/комнат, приглашения, raw errors и игровые состояния не входят в эти диагностические записи. CI загружает только JSON с именами событий, без browser trace и полных логов.
