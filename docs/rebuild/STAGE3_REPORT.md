# Этап 3 — Дурак: итог реализации

Дата: 10 ноября 2026. Ветка: `codex/arcade-rebuild`.

Реализован и проверен локально полный игровой цикл подкидного и переводного Дурака на 2–6 игроков. Live-проверка в настоящем Discord и deployment в Railway не выполнялись.

## Правила и движок

- [RULES.md](../../games/durak/RULES.md) обновлён по решениям Q1–Q8. Перевод одной/несколькими картами одного достоинства возможен до первого покрытия; цепочки разрешены при 3–6 действующих игроках. При двух запрещён возврат исходному атакующему. Проверяются полный размер атаки и рука нового защитника, включая пустую руку.
- Чистая детерминированная state machine: 36 карт, seeded shuffle, раздача по кругу, младший козырь, атака, защита, очередное подкидывание, взятие с доподкидыванием, отбой, добор и выход игроков.
- Все переходы immutable; проверяются сохранение 36 уникальных карт, допустимость покрытия, лимит стола, состав и очередь. Время передаётся движку сервером.
- Учитываются полный круг переводов, исходный атакующий как финальный защитник, выход защитника после отбоя, совместный выход последних игроков, ничья и последний проигравший.
- Рейтинговые очки не начисляются: новые результаты сохраняют `ratingDelta=0`, существующий рейтинг не меняется. Сохраняются история, победы, поражения и ничьи. Экономика и ставки не подключены.

## Multiplayer и сохранение

Дурак зарегистрирован как исполняемый `GameModule`. Комната поддерживает режим, вместимость 2–6, приватные приглашения, ready и запуск. Каждое HTTP/Socket.IO действие проходит проверку сессии, участия, версии, requestId, структуры и правил игры.

Checkpoint, seed, колода, чужие руки и полный журнал остаются на сервере. Клиент получает свою руку, публичный стол, число карт соперников и персональные разрешённые действия. Сериализация и replay воспроизводят как игровые, так и системные действия.

Состояние, журнал и результаты сохраняются в PostgreSQL `arcade` атомарно. Повторы не создают второй ход или вторую статистику. Данные восстанавливаются новым процессом backend. Существующая структура таблиц достаточна: новых SQL-миграций на этапе 3 нет.

Каждое решение ограничено 30 секундами: авто-атака, взятие или пас. При отсутствии heartbeat всех участников партия приостанавливается; при возвращении сохраняется остаток времени. После рестарта активный неприостановленный матч получает минимум 30 секунд, пропущенные ходы не выполняются каскадом. Системные действия недоступны клиенту.

Обнаруженный при E2E дефект исправлен: ошибка одного checkpoint или его времени больше не останавливает таймеры остальных столов и рассылку состояний. Добавлен regression-тест. В журнал пишутся только matchId и класс ошибки. Тестовые матчи с искусственным временем закрываются после тестов без удаления истории.

Также исправлены конфликт готовности при одновременном обновлении лобби и общий HTTP rate-limit для нескольких авторизованных игроков за одним Discord/NAT proxy. Только подтверждённые личности получают индивидуальные лимиты; поддельные токены остаются в IP bucket.

## Интерфейс

Добавлены отдельный карточный стол, авторские SVG-карты и рубашки, козырь и колода, аватары/счётчики соперников, текущий ход, таймер, серверная подсветка, выбор цели защиты, перевод нескольких карт, контекстные действия и результаты. Есть анимации карт и настройка reduced motion. В мобильной версии рука прокручивается внутри стола; страница не имеет горизонтального переполнения.

Дурак доступен в библиотеке, UNO/Мафия остаются «Скоро». Sandbox скрыт в production. Клиентская логика не заменяет серверную проверку правил.

Снимки последнего Playwright-прогона находятся в `tests/.artifacts/`: `durak-desktop.png`, `durak-mobile-active.png`, `durak-six-mobile.png`, `durak-transfer.png`, `durak-result.png`, `durak-mobile.png`. Desktop и мобильный стол визуально просмотрены. Это локальные артефакты, не опубликованные изображения.

Он проверяет инварианты и отдельные ограничения стратегии, записывает seed при превышении бюджета ходов вместо объявления такого случая победой. ## Запуск

Из корня репозитория:

```powershell
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:local
```

Первый терминал оставьте открытым. Во втором:

```powershell
pnpm db:migrate:local
pnpm db:migrate:test
pnpm dev
```

Откройте `http://127.0.0.1:5173` в двух независимых браузерных контекстах. Войдите локально, создайте комнату Дурака, выберите режим и вместимость, присоедините второго игрока, отметьте готовность и начните партию. Для защиты выберите свою карту и атакующую карту на столе. Для перевода выберите одну или несколько подсвеченных карт одинакового ранга и «Перевести».

Для проверок остановите `pnpm dev`, сохранив PostgreSQL работающим:

```powershell
pnpm check
pnpm exec playwright install chromium
pnpm test:e2e
pnpm test:durak:sim
```

Подробности: [README](../../README.md), [конфигурация](../CONFIGURATION.md), [PostgreSQL](../DATABASE.md).

## Discord, Railway и границы проверки

Настройки Portal и live-checklist: [DISCORD_SETUP.md](../DISCORD_SETUP.md). Нужны Activity, root URL Mapping на HTTPS Arcade, CDN mapping, согласованный Application ID, новый Client Secret только на backend, scope `identify` и доступ тестировщиков. Production использует Discord auth и отключённый sandbox/mock.

Deployment: [RAILWAY_DEPLOYMENT.md](../RAILWAY_DEPLOYMENT.md). Подготовлен Dockerfile и healthcheck; начальная конфигурация — одна реплика с отдельной Arcade-БД. Runtime не запускает миграции автоматически. Production-миграции требуют отдельного согласования целевой БД и SQL.

В настоящем Discord ещё нужно проверить OAuth consent/отказ, Activity participants/context, proxy/WebSocket/CSP/CDN, реальные аватары, desktop/web/mobile, сворачивание приложения и полные партии 2–6 реальных пользователей. Автоматические OAuth-тесты используют синтетический транспорт; они не являются проверкой реального Discord.

Docker build, Railway deployment, Linux CI и многорепличная нагрузка в этой среде не проверялись. Глобальная DB-блокировка, replay при чтениях и polling подходят для начального объёма; перед масштабированием нужны нагрузочные измерения, оптимизация replay и координация таймеров между репликами. Большая задержка event loop не создаёт серию «догоняющих» автоходов, но может задержать одно действие. Тесты и симуляции не доказывают отсутствие всех возможных ошибок.

База Python-бота, его таблицы/экономика и пользовательские данные не изменялись. Production-соединений и миграций не было. Защищённый `SECURITY.md` сохранён: найдена одна ранее существовавшая строка, похожая на секрет; значение не выводилось и не копировалось.
