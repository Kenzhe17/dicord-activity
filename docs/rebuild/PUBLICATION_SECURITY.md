# Подготовка публикации GitHub

Цель: `Kenzhe17/dicord-activity`, только ветка `codex/arcade-rebuild`. Push требует отдельного подтверждения владельца. `main` не обновляется; force push, `--all`, `--mirror` и отправка backup-веток не используются.

## Найдено в старом проекте

В 83 старых коммитах обнаружен Discord Client Secret: Gitleaks 8.30.1 указал два вхождения в `SECURITY.md`, строки 15 и 20, коммит `46ed6311783988dfa7d432c041ad94a3cfa4c464`. Дополнительный поиск точного значения во всех доступных локальных Git blobs нашёл один содержащий его blob, только по пути `SECURITY.md`. Значения не выводились, сетевые попытки проверить действительность секрета не выполнялись.

Старые `.env.example`, `apps/web/.env.example`, `apps/web/.env.production` и `SECURITY.md` были отслеживаемыми. Все четыре исключены из индекса без удаления с диска. Добавлены правила игнорирования `.env*`, локального `SECURITY.md`, ключей/сертификатов, файлов credentials/connection и тестовых артефактов. Новый код не читает старые env-файлы. Docker context уже исключает env и SECURITY.md.

Одного удаления файлов из последнего коммита недостаточно: их содержимое остаётся в предках. Поэтому публикация подготовлена новым корневым коммитом, без родителей. Это отдельная история; обычный PR к старой `main` не будет иметь общей базы. Будущее объединение/замена основной ветки требует отдельного решения владельца.

Исходная история сохранена в локальных `main` и `backup/pre-rebuild` на `165bca0e6b1b0bcaa213ca0897342947ecbe4c71`. Эти refs не входят в отправку новой ветки. Ничего не удаляется из `.git`, резервных копий или старой удалённой `main`.

## Проверки публикуемого содержимого

- Gitleaks со стандартными правилами и полностью скрытыми значениями в локальных отчётах.
- Узкое исключение в `.gitleaks.toml`: только синтетический публичный Application ID теста OAuth, только конкретное значение и файл `apps/server/src/platform.test.ts`. Для секретов, токенов и целых каталогов исключений нет.
- Проверка всех файлов индекса и истории новой ветки, отсутствия env, приватных ключей, сборок, зависимостей, браузерных traces, дампов БД и Git-backup объектов.
- Дополнительное сравнение с известным унаследованным секретом и локальными реквизитами PostgreSQL без вывода значений.
- Сопоставление удалённых старых путей с reset manifest и проверка сохранности лицензий/локальных защищённых оригиналов. `.gitignore` намеренно дополнен в рамках подготовки публикации; исходный вариант сохранён в старой истории.
- `git diff --cached --check`, конфигурация remote и точный refspec. Проверка `ls-remote` на момент подготовки показала отсутствие удалённой ветки `codex/arcade-rebuild`.

Результат проверки индекса: 129 файлов, 0 находок Gitleaks после единственного точечного исключения тестового публичного ID, 0 совпадений с известными приватными значениями, 0 запрещённых путей, 0 удалений вне согласованного reset manifest и четырёх исключённых локальных файлов. Все четыре исключённых оригинала существуют на диске. Из семи защищённых файлов изменён только `.gitignore` для предотвращения повторного добавления; остальные SHA-256 совпадают. TypeScript и ESLint повторно пройдены при подготовке публикации.

В CI добавлен Gitleaks 8.30.1 с фиксированным SHA-256 Linux-архива, проверкой истории текущей ветки и редактированием секретов в выводе. Источник и описание параметров: [официальный Gitleaks](https://github.com/gitleaks/gitleaks). Удалённый запуск CI произойдёт только после разрешённого push; его результат пока неизвестен.

## Перед реальным использованием Discord

Ранее опубликованный Client Secret следует считать раскрытым: владелец должен отозвать/заменить его в Discord Developer Portal и внести новый только в защищённые переменные окружения backend. Новая ветка не очищает старую удалённую историю, forks, клоны и caches. Ротация или удаление старой истории удалённого репозитория в этой работе не выполнялись.

Полный прогон этапа 3 ранее прошёл: 61 тест Vitest, 5 Playwright-сценариев, 100 000 симуляций, typecheck/lint/build и smoke с перезапуском. При подготовке публикации игровая логика не изменяется. Сведения об ограничениях: [STAGE3_REPORT.md](STAGE3_REPORT.md).

## Отправка после подтверждения

Перед отправкой повторно проверить чистоту рабочего дерева, SHA коммита и отсутствие неожиданной удалённой ветки. Отправлять только явный refspec, без тегов:

```powershell
git -c push.followTags=false push --set-upstream origin refs/heads/codex/arcade-rebuild:refs/heads/codex/arcade-rebuild
```

Если удалённая ветка появилась или изменена кем-то ещё, остановиться для сверки. Force push не применять.

После публикации Railway должен собирать именно `codex/arcade-rebuild`: один Docker-сервис раздаёт frontend/backend, отдельный PostgreSQL обслуживает схему `arcade`. Развёртывание и production-миграции не входят в эту подготовку; см. [инструкцию Railway](../RAILWAY_DEPLOYMENT.md).
