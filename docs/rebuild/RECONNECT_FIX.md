# Восстановление соединения после штатного рестарта

Исходный сбой: [CI 42858407747](https://github.com/Kenzhe17/dicord-activity/actions/runs/42858407747), коммит `a523ce7`, `tests/e2e/durak.spec.ts:95`.

## Причина

`preClose` вызывал `io.disconnectSockets(true)` перед `io.close()`. На клиент приходил `io server disconnect`: Socket.IO удалял подписки Manager и больше не пытался подключиться. Первый браузер восстанавливался благодаря reload; второй оставался отключённым. Это не потеря PostgreSQL-состояния и не просто медленное обновление индикатора.

Такое поведение описано в [Socket.IO client lifecycle](https://socket.io/docs/v4/client-socket-instance/#disconnect). На Windows `child.kill('SIGTERM')` принудительно завершает процесс, обходя штатный обработчик; на Linux CI тот же вызов проходит через graceful shutdown. Различие документировано в [Node.js child_process](https://nodejs.org/api/child_process.html#subprocesskillsignal).

Новый regression-тест до исправления воспроизвёл `io server disconnect` у обоих клиентов вместо ожидаемого `transport close`. После замены shutdown на `await io.close()` этот тест прошёл. Проверка не основана на увеличении Playwright timeout: ожидание статуса по-прежнему 5 секунд.

## Изменения

- Backend закрывает Socket.IO транспорт через `io.close()`; автоматический reconnect сохраняется. Logout и отзыв сессии по-прежнему отключают namespace намеренно и не вызывают цикл повторных входов.
- `apps/web/src/realtime.ts` связывает жизненный цикл соединения с повторной подпиской. «Подключено» появляется после acknowledgment и свежего персонального состояния матча. Старые callbacks игнорируются; retry подписки отменяется при disconnect/cleanup. Игровые действия не переотправляются автоматически.
- Диагностика клиента/сервера содержит только разрешённые поля. Raw errors, access/session tokens, заголовки, приглашения, идентификаторы игроков и руки не логируются.
- E2E использует реальный отдельный backend-процесс. На Linux отправляется SIGTERM; тестовый IPC-wrapper на Windows вызывает тот же production-обработчик. HTTP-админ endpoint и тестовый код в production-сервер не добавлялись. Watchdog считает принудительную остановку ошибкой теста.
- Тест подтверждает отсутствие reload у `b` по `performance.timeOrigin`, новое WebSocket-состояние после рестарта, сохранность обеих рук/стола, согласование версий, отсутствие закрытых данных соперника и идемпотентность последнего запроса.
- Интеграционный тест выполняет дополнительный ход, пока транспорт отключён, и проверяет доставку последнего состояния обоим клиентам. Отдельно проверены terminal logout, отложенный acknowledgment, очистка retries и безопасные диагностические сообщения.
- Vitest-файлы запускаются последовательно: они используют общую локальную `arcade_test`, и фоновые poller разных файлов иначе меняли чужие fixtures. Проверки конкурирующих запросов/нескольких клиентов внутри тестов сохранены.
- Linux CI запускает весь E2E-набор, затем три повтора полного сценария Дурака с рестартом. В artifacts включаются только отфильтрованные `reconnect-diagnostics.json`; traces с сетевыми данными не загружаются.

В каждом повторном E2E диагностические записи подтверждают два штатных закрытия backend и две синхронизации клиента `b`. Идентификатор документа второго браузера не меняется; актуальное состояние приходит через новый WebSocket. Начальная отдельная проверка полного сценария тоже прошла.

Локальная среда — Windows; WSL сообщает `REGDB_E_CLASSNOTREG`, Docker недоступен. Три повторных Linux-прогона включены в workflow и требуют публикации исправления. Результат нового Linux CI нужно проверять по SHA отдельного коммита. До его успешного завершения исправление не считается подтверждённым для CI. Railway deployment, production-миграции, изменение `main` и force push не входят в эту работу.
